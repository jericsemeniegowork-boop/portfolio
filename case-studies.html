Main Case Study

Internal Service Filing Workflow — a realistic filing and record management module.

Internal Service Filing Workflow

Test coverage was built for an internal service filing workflow covering UI behavior, form validation, record management, data integrity checks, end-to-end workflow execution, document generation, and Jira issue tracking. Test cases were written in Excel first, then organized into an RTM before execution started.

What Was Tested

  • Repository list page — columns, search, filter, sort, pagination
  • Add new entry form — required fields, validation, submit flow
  • Record detail view — data accuracy and action buttons
  • Edit and status update — save, cancel, success message
  • Document generation — file opens and data is correct
  • Data consistency across list, detail, and generated document

Tools Used in This Case Study

  • Excel — test cases written and tracked here
  • RTM — maps each requirement to its test cases
  • Jira — defects logged with full replication steps
  • Browser DevTools — console and network tab for evidence

Defect Sample

Anonymized defect logged during the time management workflow testing.

Back Button Navigation Redirects to Incorrect Page

Medium Severity
ModuleTime Management — Navigation
SeverityMedium
PriorityHigh
DescriptionThe Back button does not return the user to the most recently accessed page. The issue appears across multiple screens in the module, which suggests a shared navigation handler is the cause rather than a single screen bug.
Steps1. Open the time management module.
2. Navigate to a sub-panel or detail page.
3. Click the Back button.
4. Observe which page the system navigates to.
ExpectedSystem returns to the most recently accessed page or panel.
ActualSystem skips the previous panel and navigates to an earlier page in the flow.
ImpactBreaks the navigation flow, increases the time it takes to complete a task, and risks data loss if users navigate away from an unsaved form unintentionally.
