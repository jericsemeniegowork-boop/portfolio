Testing Types

A concise reviewer of testing types I understand and how they connect to my QA portfolio. My strongest area is manual functional testing, regression testing, UAT support, defect retesting, and release validation.

Functional Testing

Validates that the system behaves according to requirements. In my portfolio, this covers create request, submit, approve, reject, status update, and read-only behavior.

Used in portfolio

Non-Functional Testing

Checks how well the system works, such as usability, compatibility, reliability, security-related behavior, and basic performance observation.

Basic awareness

Manual Testing

Human-driven testing without automation scripts. This is my main focus: executing test cases, validating workflows, documenting defects, and supporting UAT.

Main strength

Automation Testing

Uses scripts and tools to run stable tests repeatedly. I have basic Selenium/Python awareness and I am open to growing into automation.

Supporting exposure

Black Box Testing

Testing without seeing the code. Most manual QA work is black box: provide input, follow the workflow, and compare actual vs expected result.

Used in portfolio

White Box Testing

Testing with code visibility, usually handled by developers or automation engineers. I understand the concept, but I do not position this as my main strength.

Concept awareness

Gray Box Testing

Testing with partial technical knowledge. My supporting API, SQL, Browser DevTools, and Selenium/Python samples show basic gray-box awareness.

Supporting awareness

Regression Testing

Ensures new changes or fixes do not break existing features. In my portfolio, regression covers create, submit, approve/reject, status, and history checks.

Main strength

Smoke Testing

A quick build health check to confirm the main workflow is stable enough for deeper testing.

Used in process

Sanity Testing

A focused check after a small fix. Example: retesting the approved request read-only fix before wider regression.

Used in process

Exploratory Testing

Testing with curiosity beyond scripted steps. Example: trying repeated clicks, browser back, unusual values, and role switching.

Manual QA skill

Alpha and Beta Testing

Alpha is internal testing before wider release. Beta is testing by selected real users before full launch. I understand where these fit in the release cycle.

Concept awareness

Testing Levels and Execution Types

These are common test levels and execution types I understand. I connect them to my portfolio where applicable, while keeping my strongest positioning as manual QA.

Unit Tests

Low-level tests close to the source code. They validate individual methods, functions, classes, components, or modules. These are usually developer-led and often automated because they are fast to run.

Concept awareness

Integration Tests

Verify that different modules, services, or systems work together, such as application-to-database interaction or service-to-service communication.

Supported by API/SQL awareness

Functional Tests

Focus on business requirements and expected output. They check whether a user action produces the correct result according to the requirement.

Used in portfolio

End-to-End Tests

Replicate a real user journey in a complete environment. Example: requester creates a request, submits it, approver approves it, and the system updates the status.

Used in portfolio workflow

Acceptance Testing

Verifies whether the system satisfies business requirements and user expectations. UAT is a common form of acceptance testing.

Used through UAT checklist

Performance Testing

Evaluates speed, reliability, scalability, and responsiveness under workload. As manual QA, I can observe slow pages, delays, timeouts, and report performance concerns.

Basic awareness

Smoke Testing

Basic health check to confirm that major features are working and the build is stable enough for deeper testing or post-deployment validation.

Used in process
