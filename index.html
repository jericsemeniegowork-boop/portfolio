End-to-end manual QA process

This is the workflow I follow from requirement review to test reporting.

Requirement Analysis

Review BRD, SRS, or user stories and convert them into testable requirements.

  • Identify acceptance criteria
  • Clarify ambiguous rules
  • Identify risks and dependencies

Test Planning

Define the testing approach before execution begins.

  • In-scope and out-of-scope items
  • Test types: functional, regression, UAT
  • Entry/exit criteria and tools

Test Design

Create test scenarios and detailed test cases with clear expected results.

  • Positive cases
  • Negative cases
  • Edge and boundary cases
  • Requirement Traceability Matrix

Test Data Preparation

Prepare realistic data needed to execute test cases properly.

  • Valid inputs
  • Invalid inputs
  • Boundary values
  • Reusable datasets

Test Environment Setup

Confirm the QA or staging environment is ready before execution.

  • Browsers and devices
  • OS versions
  • Environment smoke check

Test Execution

Run test cases and record actual results clearly.

  • Mark Pass, Fail, or Blocked
  • Capture screenshots/evidence
  • Compare actual vs expected results

Defect Management

Log, communicate, and track issues until they are resolved.

  • Steps to reproduce
  • Expected vs actual result
  • Severity and priority
  • Lifecycle: New → Assigned → Fixed → Retest → Closed

Defect Retesting

Re-test fixed bugs to confirm the issue is truly resolved.

  • Validate same steps
  • Check related behavior
  • Update ticket status

Regression Testing

Re-run impacted test cases to ensure new changes did not break existing features.

  • Fixed issue coverage
  • Related workflow coverage
  • Critical path checks

Test Reporting

Summarize results, defects, coverage, blockers, and release risks.

  • Pass/fail rate
  • Defect count
  • Coverage summary
  • Release recommendation

Manual QA case study: Purchase Request & Approval Workflow

Business scenario

A requester creates a purchase request, submits it for approval, and an approver either approves or rejects it. The system must enforce required fields, correct status transitions, role permissions, audit history, and read-only behavior after approval.

Scope
Covered workflows

Create request, submit, approve, reject, search, status tracking, audit trail, and regression checks.

Risk
Key risk areas

Wrong status, unauthorized approval, missing validation, editable approved request, and broken regression flow.

Output
QA artifacts

Test plan, RTM, test cases, test data, defect report, regression checklist, and test summary report.
