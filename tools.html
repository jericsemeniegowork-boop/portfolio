Tools Used in QA Work

Every tool here was used in actual work — tickets, regression cycles, defect reports, or data checks. The descriptions below say exactly what each tool was used for and how.

Main Tools — Used Daily at Accenture

ServiceNow

The primary ticketing platform at Accenture. Used every day to log issues found in SAP testing, record validation notes, track escalations, and complete close-out documentation — around 10 tickets a day.

SAP S/4HANA

The main system tested at Accenture. Each business process module was run step by step to find workflow failures, data mismatches, access issues, and patch-related defects before every release.

Excel / Google Sheets

Where all test cases were written before execution, execution results were tracked, RTM documents were built, and test summary reports were prepared. Used in every role and in all portfolio case studies.

SharePoint

Used at Accenture to store and share test documentation, QMS references, process notes, and release-related records across the team during the project.

Jira

Used at Accenture alongside ServiceNow for sprint-based defect tracking — logging bugs from SAP and web testing, tracking them through the fix and retest cycle, and reporting open counts at sprint end.

Browser DevTools

Opened with F12 during most testing sessions to check the Console tab for JavaScript errors and the Network tab for failed API calls. Screenshots from DevTools go directly into defect reports as evidence.

Automation & API Tools — Used at Accenture and HCLTech

Selenium + Python

Used at Accenture and during HCLTech training to run Python scripts that checked UI elements and key workflow steps automatically during regression cycles — faster and consistent across every run compared to manual re-checking.

Postman + JavaScript

Used at Accenture to send test requests to API endpoints, check that status codes and response data were correct, and confirm error handling worked. JavaScript scripts in the Tests tab ran the pass/fail checks automatically after each request.

SQL

Run against the database at Accenture after SAP workflow steps to confirm the correct data was actually saved — not just that the screen said success, but that the database record matched what was expected.

Additional Tools

Python

Used specifically for writing Selenium test scripts at Accenture and HCLTech — automating browser interactions to verify UI behavior and workflow stability during regression cycles.

JavaScript

Used inside Postman to write the test assertions that automatically check API responses — status codes, response body fields, and error message validation.

GitHub

Used to manage and publish the QA portfolio — all case study files are version-controlled here and served through GitHub Pages.
